# SauceDemo – E-Commerce Manual Testing Project

## 1. Project Overview

This project demonstrates my practical understanding of manual software testing through the preparation and organisation of testing documentation for SauceDemo, a demo e-commerce web application.

The project covers functional requirements, test strategy, test scenario identification, test case design, traceability, defect documentation, test execution evidence, regression test case preparation, and project reporting.

This project forms part of my QA portfolio and demonstrates my understanding of structured, documentation-driven manual testing practices.

## 3. Project Objectives

- Understand and document the application's functional requirements.
- Prepare project overview and test strategy documentation.
- Identify test scenarios based on application functionality and requirements.
- Design structured test cases with clear test steps and expected results.
- Maintain traceability between test scenarios and test cases.
- Document identified defects in a structured bug report.
- Organise screenshots related to defects and test execution.
- Prepare regression test cases to support repeated testing.
- Summarise project information and test execution outcomes.
- Maintain organised and traceable QA documentation.

## 4. Testing Scope

The project documentation covers the following testing activities:

- **Requirements documentation:** Documenting functional requirements and project information.
- **Test planning:** Defining the testing approach through the test strategy.
- **Test scenario design:** Identifying functionality and conditions to be tested.
- **Test case design:** Documenting detailed test cases with steps and expected results.
- **Traceability:** Mapping test scenarios to their corresponding test cases.
- **Defect documentation:** Recording identified defects in a bug report.
- **Test execution evidence:** Organising screenshots associated with test execution.
- **Regression testing preparation:** Maintaining test cases for regression testing.
- **Project reporting:** Consolidating project information and recorded execution results.

The detailed functionality covered by the project is documented in the functional requirements, test scenarios, test cases, and test strategy.

## 5. Testing Process

The project follows a structured testing workflow:

1. Review the functional requirements and project overview.
2. Define the testing approach using the test strategy.
3. Identify test scenarios for the functionality within scope.
4. Design detailed test cases with test steps and expected results.
5. Map test scenarios to test cases using the traceability matrix.
6. Execute the test cases and record the outcomes.
7. Document identified defects in the bug report.
8. Organise screenshots related to defects and test execution.
9. Prepare regression test cases for relevant functionality.
10. Summarise the project and recorded test execution results.

This workflow demonstrates the relationship between requirements, test design, traceability, execution, defect documentation, regression testing, and reporting.
