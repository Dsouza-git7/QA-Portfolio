# Trello API Testing Project – Postman

## 1. Project Overview

This project demonstrates practical API testing skills through testing Trello REST APIs using Postman.

The project focuses on API request execution, response validation, test scenario identification, test case design, defect identification, and test execution reporting.

It forms part of my QA portfolio and demonstrates my understanding of REST API testing, API documentation, and structured testing practices.

## 3. Project Objectives

- Understand Trello REST API functionality and available endpoints.
- Review API documentation and request requirements.
- Design positive and negative API test scenarios.
- Prepare structured API test cases.
- Execute API requests using Postman.
- Validate HTTP status codes and response data.
- Verify API behaviour against expected results.
- Identify and document API defects.
- Maintain organised API testing documentation.
- Analyse and summarise test execution results.

## 4. Testing Scope

The project focuses on functional testing of Trello REST APIs.

Testing activities include:

- API endpoint validation.
- HTTP request execution.
- Request parameter and payload validation.
- Response status code validation.
- Response body and data validation.
- Positive and negative test scenarios.
- Authentication and error handling, where covered by the test cases.
- Defect identification and reporting.

The specific API resources and operations tested are documented in the test scenarios, test cases, and Postman collection.

## 5. Testing Process

The project follows a structured API testing workflow:

1. Review Trello API documentation.
2. Understand the available API endpoints and request requirements.
3. Identify relevant API test scenarios.
4. Design test cases with preconditions, request details, and expected results.
5. Configure and execute API requests using Postman.
6. Validate response status codes and response data.
7. Record actual results and execution status.
8. Document identified defects with supporting evidence.
9. Prepare the test execution summary.

## 10. Interview Revision Notes

When discussing this project during interviews, I should be prepared to explain:

1. **Project objective:** The purpose of testing Trello REST APIs.
2. **API fundamentals:** REST API concepts and client-server communication.
3. **API endpoints:** The Trello API resources and endpoints covered in the project.
4. **HTTP methods:** The methods used and their purpose.
5. **Request structure:** Endpoints, headers, parameters, authentication, and request bodies.
6. **Response validation:** How status codes and response data were validated.
7. **Postman:** How requests and collections were organised and executed.
8. **Negative testing:** How invalid inputs and error scenarios were tested.
9. **Defect reporting:** How API issues were identified and documented.
10. **Test execution results:** How to explain the 51 test cases, 49 passes, and 2 failures.

Before discussing a specific API failure in an interview, review the corresponding request, response, expected result, actual result, and defect documentation.
